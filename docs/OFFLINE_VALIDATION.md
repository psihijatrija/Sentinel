# Offline and privilege validation for 3.2.3

The Linux build environment can compile the complete net48-windows solution and run portable policy/transport/IPC checks against the resulting Core assembly. It cannot exercise Windows Firewall COM, access tokens, service installation, the WinForms dashboard, or the Windows .NET Framework test host.

Before publishing an installer, run the full Windows build/test suite and validate on an isolated Windows VM:

1. Install/upgrade as administrator. Confirm six enabled Sentinel-Offline-* block rules use the current installed executable paths, both directions, all protocols, and Domain/Private/Public profiles. Confirm non-loopback IPv4/IPv6 ranges exclude 127/8 and ::1. Check the firewall service and profiles are enabled. Test effective TCP/UDP blocking against controlled LAN and public IPv4/IPv6 endpoints from each Sentinel executable; inspect effective rules, not just configured local rules (enterprise policy may override local policy).
2. Start the Agent normally as a standard user and as a UAC-filtered administrator. Confirm its token is not SYSTEM/elevated and the dashboard, history, scan requests, and service-authorized certificate operations work. Launching the Agent elevated must refuse to run. Restart the Agent via the service watchdog and verify its replacement still has a limited token. A full administrator session without a limited linked token must not produce an elevated Agent.
3. Confirm localhost HTTP/WebSocket UI and named-pipe IPC work while the external blocks are present. No internet reputation/feed/public-IP/DNS-validation/connectivity/report attempts should occur. Confirm standard-user logs/restart markers are writable without modifying service audit data.
4. Stop the service and verify the Agent still opens with reduced capability; administrator operations report the helper unavailable and never elevate or quarantine the supplied file. Module inspection must not report a requested scan as a completed quarantine.
5. Supply old encrypted online settings and cached reputation data. Confirm reporting remains disabled, online verdicts remain Unknown, and local analysis uses its new cache namespace. With no local KEV/IOC snapshot, coverage must be reported as missing rather than fresh/clean. Check Authenticode operations do not fetch remote certificate URLs. Signing-root shape enrichment is omitted on runtimes such as net48 that cannot disable automatic chain downloads; explicit certificate distrust policy remains active.
6. Test oversized, malformed, stalled, replayed, and unauthenticated pipe requests. Verify request-read slots recover after five seconds and remote/network-logon clients cannot connect. Authenticated operations must remain limited to the existing allowlist; a request cannot supply a command or authorize arbitrary privileged deletion.
7. Upgrade twice and change the install path in a test VM; verify fixed rule identifiers point to the new binaries without accumulating duplicates. Disable a firewall profile or apply a policy that rejects local rules; verify visible failure and continued offline detection. Re-enable it and verify reconciliation succeeds.
8. Uninstall and confirm owned self-block rules are removed while unrelated firewall rules remain intact.

The service remains SYSTEM because it hosts native/ETW sensors and response. This release does not claim a minimal broker architecture or containment after SYSTEM compromise. Network traffic brokered by other OS processes and local untrusted parsing require separate defenses. Keep Windows/.NET and dependencies patched.

Additional policy-store and runtime checks:

- Run `tests/Sentinel.Tests/LocalFirewallPolicy.Tests.ps1` (also wired into Windows CI). Its mock stores verify local/GPO inbound disabling, outbound/block preservation, DHCP and essential IPv6 exemptions, Windows re-enables/new rules, explicit approval and changed-filter revocation, domain conflict reporting, unsupported-GPO fallback, mutation-crash recovery, original-state rollback, profile enablement/restoration, and corrupt-journal failure.
- On Windows, test effective Group Policy merge with local-rule merging disabled, enabled local GPO blocks, domain rules with conflicting identifiers/filters, and domain inbound allow rules. Confirm domain GPOs are never written. Recheck after `gpupdate` and reboot; inspect ActiveStore and actual controlled connectivity, not registry values alone.
- Re-enable an unapproved inbound allow rule and add a new one. Confirm notification-driven/fallback reconciliation disables it without deleting it. Approve an exact rule with `--allow-inbound PersistentStore 'Name'` (or `localhost`), reboot, and verify its enabled state survives. Change its program/port/security filters and confirm approval no longer applies. Revoke with `--deny-inbound`. Confirm a non-elevated Agent cannot change these approvals through IPC.
- Validate DHCPv4/DHCPv6 renewal, IPv6 neighbour discovery, router discovery, and path-MTU handling; outbound connections must remain usable. Unused inbound services must remain closed. Echo and arbitrary app ICMPv6 exceptions should remain disabled unless approved.
- Exercise actual Windows token/service lifecycle, simultaneous administrator approval and reconciliation, a stopped firewall service, missing NetSecurity/PowerShell, an invalid or unsafe rollback journal, and both complete/partial uninstall rollback. A failed rollback must stop uninstall before program files are removed. Confirm no UI green status when verification is stale or conflicted.
- Replay network-active Defender/browser/game parent processes spawning ordinary children versus encoded/evasive scripts. Verify ordinary children do not alert, evasive scripts emit Tier2 LogOnly context, expired/reused PIDs do not inherit exposure, and game/anti-cheat handle safety remains intact. These checks are behavioral coverage, not a claim to detect unknown exploits universally.

Authoritative policy-store semantics reviewed: [Get-NetFirewallRule](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallrule), [New-NetFirewallRule](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule), and [Set-NetFirewallProfile](https://learn.microsoft.com/en-us/powershell/module/netsecurity/set-netfirewallprofile).

The Build & Test workflow now also runs `tools/validation/WindowsFirewallSmoke.ps1` on a separate disposable GitHub-hosted Windows runner. It uses a dedicated net48 executable host with binding redirects, exercises real local/local-GPO policy stores, verifies that an identical harmless executable connects before blocking and is blocked afterward while a control still connects, preserves loopback, checks approval/reconciliation and rollback, and refuses to run outside that disposable CI context. This does not replace domain-joined, reboot, or interactive token validation.

Windows CI validation on the 3.2.3 branch completed the full .NET Framework suite: 2,852 passed, zero failed or skipped, with a zero-warning Release build. Firewall policy regressions, Worker tests and dashboard tests also passed. Real firewall smoke and the interactive/domain/reboot checks above are separate gates. A timed-out initial inventory recovered through its journal and restored 90 changed rules on the disposable runner. Policy operations remain cancellable and bounded to ten minutes to accommodate initial CIM inventories; the dashboard remains unverified/stale until an effective-policy check completes.

The disposable Windows firewall smoke passed on 2026-10-17 (workflow run 39022019925, product-code commit b878b525c6afe8191d4d0b762fa3b6447f059e92): all six blocks were effective; the Agent-path TCP client was blocked externally while an identical control connected; loopback remained usable; local and local-GPO inbound rules were retained disabled; Windows-style re-enable was reconciled; approval persisted; original local/GPO states were restored and all six effective owned rules were removed. This validates the tested IPv4 TCP path and policy stores, not every protocol/address-family combination or the remaining interactive/domain/reboot checklist.
